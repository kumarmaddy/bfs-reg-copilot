# ADR-0019: Baseline API: small, local-only, one request at a time

- Status: Accepted
- Date: 2026-11-25
- Deciders: Project owner

## Context

Slice 2.7 puts the baseline pipeline behind HTTP so that a person or another program can ask a
question and get an answer with its sources. It is not the production service (Phase 4). The
choices below are the ones that would be expensive to reverse or that a reviewer in a bank would
ask about first.

## Decision

1. **FastAPI and uvicorn, pure-Python dependencies only.** Application Control on the project
   machine blocks native launchers, so the server runs as `python -m bfs_reg_copilot.api`. The
   optional native accelerators (`uvloop`, `httptools`) are not installed. FastAPI gives a
   generated OpenAPI description for free.
2. **Two operations:** `POST /ask` (question in, answer and citations out) and two probes:
   `GET /health` (the process is up; touches nothing else) and `GET /ready` (database and model
   reachable). Probes are separate so an orchestrator can tell "restart me" from "wait".
3. **Every citation carries lineage:** source id, section path, page title, URL, the time we
   retrieved the page, the publisher's page date when there is one, and the SHA-256 of the exact
   page version (metric M9). A citation that does not match a retrieved passage is **dropped and
   counted** in `unverified_citations`; it is never shown.
4. **Three outcomes, stated explicitly:** `answered` (at least one verified citation), `refused`
   (the model declined), and `uncited` (the model answered but no citation could be verified).
   `uncited` exists because the baseline does not repair or block such answers (ADR-0018, point
   5). A client must not present an `uncited` answer as supported. Blocking it is a Phase 3
   guardrail, to be judged against the baseline.
5. **One request at a time.** The pipeline holds one database connection and one local model, and
   neither is safe to share across threads. Requests queue on a lock for up to 60 seconds, then
   get `503 busy` with `Retry-After`. This is a known limit, not a design goal; metric M3 and
   concurrency are Phase 4.
6. **Failures are classified and never leak internals.** A dependency failure (database, embedder,
   model) is `503` and the backend is rebuilt on the next request, so a dropped connection
   heals. Unusable model output is `502`, and the raw reply is not returned. Anything else is a
   `500` with a fixed message: a bug in our own code is not reported as "try again". Details go
   to the log under a request id, never to the caller.
7. **Questions are not logged.** A log line records the request id, outcome, citation counts,
   latency and the question's length. Questions may contain client details in real use. Request
   ids are generated by the server; a client-supplied id is ignored so it cannot forge log lines.
8. **No authentication, so local only.** The server listens on 127.0.0.1 and refuses any other
   address unless `--allow-remote` is passed. Authentication, TLS and rate limiting are Phase 4
   work, and the flag exists so that removing the protection is a visible, deliberate act.
9. **Questions are limited to 2,000 characters and unknown request fields are rejected.** The
   retrieval depth (k) is fixed by the server and is not a request parameter, so a caller cannot
   change what the evaluation measured.

## Consequences

- The API is evaluable as a unit without a database or a model (a fake pipeline), and the
  evaluation harness is unchanged: it still calls the pipeline directly, so API changes cannot
  move the M1 baseline.
- A reviewer can see exactly what the baseline does not do: no authentication, no concurrency, no
  blocking of uncited answers, no input scanning for injected instructions (RAID I-5).
- If a cloud model is used later, a hosted gateway still returns the same shapes; the API does
  not change.

## Alternatives considered

- **Starlette alone:** one fewer dependency, but no generated OpenAPI and less familiar to
  reviewers. FastAPI's extra weight is pure Python and small.
- **Per-request database connection:** simpler failure handling, but it adds connection setup to
  every question and hides the real failure mode. Rebuild-on-failure is the same healing with
  less cost.
- **Hiding uncited answers (`refused` instead):** looks safer, but would change the pipeline's
  measured behaviour inside the API layer. Safeguards belong in the pipeline, where the harness
  can measure them.
